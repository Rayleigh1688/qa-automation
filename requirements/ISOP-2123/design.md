## 已确认规则

| 范围／来源 | 采用规则 |
| --- | --- |
| 前提 | 两站共享会员与KYC，同会员UID相同；余额、存款、提款、交易记录、游戏列表分站独立。门店共享，域名分站 |
| §1切站 | Header在面包屑前显示Filbet／Filplay／总合；默认Filbet并记住上次选择。两单站之间切换留在原页，数据换站且列表回第1页；在线人数跟随站点，总合为两站合计 |
| §1总合 | 仅保留Pagcor税收、门店税收、报告摘要。其他页切总合或总合状态直开其他页URL，都转Pagcor税收报表 |
| §2会员 | 只列在所选站有钱包的会员；同UID可同时出现在两站。账户余额、已完／未完流水取当前站；品牌归属仍表示注册站点，不能拿它替代钱包归属 |
| §2—3门店 | 共享门店只显示和编辑当前站域名，不影响另一站。域名不得与其他门店重复，也不得同时用于两站；违反时禁止保存并说明原因 |
| §2—3资金与游戏 | 存提款、渠道／账户类型选项、交易、游戏列表和全平台注单随站点；游戏上／下线／维护仅作用当前站，操作前二次确认写明站点及游戏名称或数量 |
| §2—3报表 | 单站取本站；总合取两站合计。总合报告摘要同一UID两站均投注时人数只计一次；不能直接把两站投注人数相加 |
| §3分页、筛选与导出 | 总合Pagcor和门店税收查询一次列全、不分页；单站保留分页。全平台注单与Pagcor税收移除旧品牌归属筛选，注单品牌列保留。导出按当前站，总合报表导出两站合计 |

总合只开放报表并不授予配置操作入口；应同时核页面与请求的站点上下文。共享UID／KYC不能推导钱包、订单或游戏操作也共享，注册品牌字段不能代替实际站点过滤。

## 验证重点

最高优先级是切站后数据、选项和写入对象的一致性，以及总合的集合／金额合计与UID去重。使用仅Filbet、仅Filplay和双钱包同UID三组来源样本；金额按可追溯站点原记录对照，人群按集合并集计算，不能只比较页面内部总和。

同页切站须检查第1页重置、旧请求晚到、返回／刷新和详情／导出所属站；这些是规则的实现风险检查，不新增产品要求。门店域名和游戏状态的受控验证须有独立对象及前后快照，本次扫描未做写入。

导出先确认各入口既有全部筛选、当前页或勾选合同，再在当前站或总合口径内核完整集合；正文只明确导出的站点范围，不能据此统一规定所有入口都导出全部筛选结果。总合两类税收页面查询一次列全仍是独立明确要求。门店与游戏操作取证后按已授权方案恢复并复核两站及非目标后态；异常先冻结原失败证据，不为获得通过结果继续写入。

与[ISOP-2124](../ISOP-2124/design.md)存在身份、KYC与钱包隔离依赖。沿用既有合规报表时先核原字段和统计窗口，不把首页BI或代理GGR公式直接移植到本单；未改公式不等于可跳过分站取数和总合对账。
