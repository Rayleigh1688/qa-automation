## 问题详情

<a id="q-01"></a>
### Q-01：会员端输入精度与文案规范

**场景：** 后台弹窗明确要求小数两位，但会员端仅说明需大于0（PHP、不设最小/最大值），未说明会员端是否限制小数两位、最大输入位数、非法值提示文案及`Daily loss limit`替换后的完整页面文案。

**需要确认：** 会员端输入校验规则、错误提示及确认弹窗正式文案。

**答复：** 待确认。

<a id="q-02"></a>
### Q-02：存量`Daily loss limit`数据兼容

**场景：** 需求将`Responsible Gaming`页的`Daily loss limit`改为每日投注上限。

**需要确认：** 上线前已设定过`Daily loss limit`的存量会员，原有数值是清空重新设定、保留作废还是迁移为每日投注上限。

**答复：** 待确认。

<a id="q-03"></a>
### Q-03：进入游戏阻挡入口边界

**场景：** 当日投注额大于或等于每日上限时，会员进入游戏需阻挡并提示固定英文文案。

**需要确认：** 阻挡是否覆盖所有游戏启动接口（真实投注、各厂商进入游戏、最近游玩、收藏直连等），试玩模式是否豁免，以及接口返回的错误码约定。

**答复：** 待确认。

<a id="q-04"></a>
### Q-04：取消上限弹窗校验规则

**场景：** 正文在「设定／修改弹窗」说明原因必填、最多200字、未填提示`請輸入原因`，在「取消上限」处仅写原因必填。

**需要确认：** 取消上限弹窗是否同样限制最多200字及相同提示文案，以及确认弹窗交互细节。

**答复：** 待确认。

<a id="q-05"></a>
### Q-05：Filbet站与后端/后台排期范围

**场景：** 正文范围明确包含Filbet、Filplay两站及后台管理，但当前Jira子任务仅列出`ISOP-2398`（FilPlay H5）和`ISOP-2399`（FilPlay App）。

**需要确认：** Filbet客户端、后端API与管理后台是否同Sprint交付，以及对应开发/测试负责人。

**答复：** 待确认。

<a id="q-06"></a>
### Q-06：原型、Figma与附件截图核对

**场景：** 父单附带`vip-admin-gray.vercel.app`原型链接及3张附件截图，`ISOP-2398`附带Figma链接（`node-id=4788-15064`）及7张H5截图，本轮只读采集未下载附件或打开原型/Figma。

**需要确认：** 下载附件并打开原型与Figma核对字段顺序、金额格式、倒计时格式、提示语及分页控件。

**答复：** 待核对。

<a id="q-07"></a>
### Q-07：进游戏阻挡弹窗文案差异

**场景：** 父单`ISOP-2393`写明进游戏阻挡提示`You have reached your daily betting limit. Please try again tomorrow.`；子任务`ISOP-2398`写明弹窗文案`You have reached your daily betting limit.`，含`OK`与`View Settings`按钮。

**需要确认：** 正式上线采用哪版提示文案（是否保留`Please try again tomorrow.`），以及App（`ISOP-2399`）与Filbet是否保持一致。

**答复：** 待确认。

<a id="q-08"></a>
### Q-08：次日调整与`Remove`交互差异

**场景：** 父单`ISOP-2393`描述次日起可「调高、调低或取消」，调整后立即生效且当日再次锁定；子任务`ISOP-2398`仅描述次日`Remove`按钮恢复可点击、点击后直接移除设置（未提直接修改数值及移除是否二次确认）。

**需要确认：** 客户端次日是否允许直接修改数值，还是必须先点击`Remove`移除后再重新设定；点击`Remove`是直接生效还是需二次确认。

**答复：** 待确认。
