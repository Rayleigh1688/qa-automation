## 验收依据

下表整理来源中明确的规则；推荐的可靠性/权限场景在用例中标示为测试设计。有歧义的部分以问题编号关联，不把建议当成已批准需求。

| 验收编号 | 业务预期 |
| --- | --- |
| AC-01 | Pending/Under Review/Approved/Rejected/Resubmit Required都允许有权限人员编辑；同一笔仅一个待复核编辑，列表显示待复核标记和三张可预览缩图。 |
| AC-02 | 三证件位各可替换图片≤500KB、显示已更换并可还原；字段与图片同一申请；无变更提示“未變更任何欄位或證件照”；手机号/用户留言/状态只读。 |
| AC-03 | 提交不立即生效；核准时字段和图片一起生效，邻近分行变更同步fb.members和fb.members.kyc里的门店/分行，并按新分行重新核对现有游戏类型限制；驳回原因必填且整笔舍弃。 |
| AC-04 | 复核状态与KYC状态独立；本人不可自审，身份取登录者，无生产操作员选择器；复核完成后详情只读，不能再核准/驳回。用户于2026-09-07补充：待审核期间会员不能提交新的KYC；本需求后台编辑待复核期间同样拦截会员新提交/补件，正式资料不得被覆盖。 |
| AC-05 | 复核待处理/已处理页签含笔数；按UID、手机、First/Middle/Last Name、提交者、提交时间筛选，已处理额外按结果筛选；字段和图片diff及抽屉信息齐全。 |
| AC-06 | 审计append-only：编辑行永远保留提交时待复核，结果另增复核行；仅编辑行可展开diff；编辑/复核前后KYC状态相同；用户操作/审核行复核状态为 -。 |

## 复核表单字段清单

- 待复核列表：序号→提交时间→会员信息→变更内容→提交者→操作。
- 已复核列表：在提交者后增加复核状态、复核人、复核时间、驳回原因；操作为详情。
- 抽屉：会员UID、手机、提交者、提交时间、复核状态、复核人、复核时间、原因，以及字段/原值/新值和证件原图→新图。
- 异动记录：异动时间/操作/异动前状态/异动后状态/复核状态/备注/异动人员。仅编辑行承载可展开详情。
