## 用例详情

<a id="c01"></a>
### ISOP-2341-C01：后台维护三种方向并排序

**前置条件：** 有游戏配置管理权限；准备至少三条可编辑游戏记录。

**操作步骤：**

1. 分别设置直版、横版、皆可并保存。
2. 查看列表方向列，执行升序和降序排序。

**预期结果：** 三种值可保存并正确回显；列表有方向列且排序与列值一致。

**待确认：** —

<a id="c02"></a>
### ISOP-2341-C02：未设置与初始方向默认值

**前置条件：** 可读取经授权的初始/新游戏样本，包括FC游戏22043。

**操作步骤：**

1. 读取FC游戏22043、其他游戏及未显式设置方向的新上架游戏。
2. 检查后台显示和进入游戏时采用的方向。

**预期结果：** FC游戏22043为横版；其他已说明初始游戏及未设置/新游戏默认直版。

**待确认：** —

<a id="c03"></a>
### ISOP-2341-C03：方向修改在下次启动生效

**前置条件：** 有可重复启动的测试游戏和可设置方向的后台账号。

**操作步骤：**

1. 启动游戏并记录方向。
2. 在后台修改方向，观察当前会话，再退出并重新开启该游戏。

**预期结果：** 修改后的方向最迟在下次开启生效；具体参数联动按Q-04确认后补充。

**待确认：** [Q-04](questions.md#q-04)：FC启动参数是否随方向字段变化。

<a id="c04"></a>
### ISOP-2341-C04：App按方向配置旋转并恢复大厅方向

**前置条件：** 支持方向锁定的App测试设备；游戏方向分别设为直版、横版、皆可。

**操作步骤：**

1. 分别以直向/横向握持设备启动直版与横版游戏。
2. 对皆可游戏在游戏中转动设备。
3. 退出至大厅并检查方向。

**预期结果：** 直版/横版按配置锁定，反向握持时游戏侧躺并铺满；皆可跟随设备；回大厅恢复横向。

**待确认：** [Q-01](questions.md#q-01)：App及代表游戏的方向锁定能力。

<a id="c05"></a>
### ISOP-2341-C05：H5方向映射及旋转即时生效

**前置条件：** H5测试设备，能记录页面导航/游戏重载；准备三种方向配置。

**操作步骤：**

1. 对直版、横版、皆可分别在设备直向和横向时进入游戏。
2. 在游戏中转动设备并观察画面及页面加载状态。

**预期结果：** H5不锁设备方向；画面按配置正向/侧躺或不旋转并铺满；旋转即时调整且不重新加载。

**待确认：** —

<a id="c06"></a>
### ISOP-2341-C06：游戏画面铺满且外框控件移除

**前置条件：** App与H5各有可启动游戏。

**操作步骤：**

1. 分别进入App及H5游戏。
2. 检查游戏占屏和原外框控件。

**预期结果：** 游戏铺满屏幕；App旋转按钮、H5重新整理/讯号/全屏按钮及外框不再显示。

**待确认：** —

<a id="c07"></a>
### ISOP-2341-C07：退出游戏返回进入前页面

**前置条件：** App、H5分别从可识别的入口页面进入游戏。

**操作步骤：**

1. 使用悬浮离开按钮退出；App另用Android返回键退出。
2. 检查目标页面、方向及游戏会话是否结束。

**预期结果：** 返回进入游戏前页面；App回大厅恢复横向。H5浏览器返回行为及按钮布局确认后补充断言。

**待确认：** [Q-03](questions.md#q-03)：悬浮按钮设计与H5返回行为。

<a id="c08"></a>
### ISOP-2341-C08：多供应商方向兼容矩阵

**前置条件：** RD确认的代表游戏、设备/系统版本及每家供应商预期。

**操作步骤：**

1. 按矩阵测试EVO、PP、BNG、Hacksaw、YGR及范围内其他供应商的三种方向。
2. 记录实际旋转、锁定、满屏和退出行为，并与RD结论逐项核对。

**预期结果：** 仅按逐项确认的矩阵判定；不从FC或单一游戏外推供应商支持。

**待确认：** [Q-01](questions.md#q-01)、[Q-02](questions.md#q-02)：支持矩阵和目标设备。
