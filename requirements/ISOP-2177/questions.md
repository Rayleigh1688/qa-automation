## 问题详情

<a id="bng-q01"></a>
<a id="q-01"></a>
### Q-01：交易去重范围和冲突载荷

**场景：** 同一笔已处理回调重发；另有不同线路交易，或同一轮中使用不同`uid`的合法后续动作。

**问题点：** 正文明确不能重复处理，但已读资料尚不能确定去重作用域。只按`uid`可能串线路，只按整轮可能误吞后续交易；同`uid`的玩家、币种或金额发生冲突也需裁决。

**需要确认：** 幂等键是否包含厂商、品牌／线路与交易`uid`，同键冲突载荷采用什么处理结果？

**答复：** 待确认。由游戏后端与BNG技术对接人答复，收到后记录结论、答复人、日期和来源。

<a id="bng-q02"></a>
<a id="q-02"></a>
### Q-02：重发响应和处理中行为

**场景：** 首次交易已成功但响应丢失；重发时玩家余额已变化，或并发重发到达时首次交易尚未完成。

**问题点：** 即使第二次不扣款，返回内容仍可能被厂商解释为取消。正文要求返回处理结果，但未冻结余额／`version`等字段及处理中响应。

**需要确认：** 成功重发应返回原余额／`version`还是当前值，原交易处理中时厂商接受等待、重试还是指定状态？

**答复：** 待确认。由游戏后端与BNG技术对接人冻结响应和并发合同，并记录答复人、日期和来源。

<a id="bng-q03"></a>
<a id="q-03"></a>
### Q-03：失败重试和交易状态

**场景：** 首次交易可能真正失败、仍在处理，或已扣款但后续持久化异常；原请求同时带投注和赢款，且`round_finished=false`。

**问题点：** 对全部重复请求无条件成功会吞掉真实失败；把交易已处理等同整轮终结，会错误关闭后续动作。金额单位也不能由原字符串推断。

**需要确认：** 请提供各前态的重试与状态迁移合同，明确交易入账、整轮终结的区别及本请求金额单位。

**答复：** 待确认。由游戏后端与BNG技术对接人提供合同，收到后记录答复人、日期和来源。

<a id="bng-q04"></a>
<a id="q-04"></a>
### Q-04：历史差账处置范围

**场景：** 原异常交易在平台侧已处理，厂商侧被认为取消，并影响9月27日报表。

**问题点：** 防重修复只能证明后续请求不会重复处理，不能证明原订单及报表已经恢复。

**需要确认：** 本次是否包含原异常订单、厂商撤销后的平台处置及9月27日对账纠偏；如包含，采用什么独立交付和对账验收？

**答复：** 待确认。由产品、财务／对账与游戏后端确认范围，收到后记录答复人、日期和来源。
