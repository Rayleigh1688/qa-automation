# ISOP-2230：厂商排行榜活动优化设计

[设计](design.md) · [问题与决定](questions.md) · [测试重点](test-cases.md) · [W27扫描](../reviews/2026W27-20261016.md)

2026-10-16初扫：本次增加奖励详情展示调整、榜单展示上限和推荐游戏配置，不重定义排行计算。正文与后台原型已读，尚未核验业务实现。个人排名边界按原文“超过1000”设计，1000不提前缩写；已明确规则可直接准备测试。

## 明确规则

| 验收编号 | 规则 | 来源定位 |
| --- | --- | --- |
| AC-01 | Details依配置展示奖励，不逐一展开每个名次的奖项 | Jira Details |
| AC-02 | 榜单最多显示第1—100名；个人排名“超过1000”时Rank显示`999+`，恰好1000按字面显示`1000`，边界核对见Q-01 | Jira 排行榜第1项 |
| AC-03 | 每个参与厂商独立配置推荐游戏，字段在上榜门槛与排除游戏之间；未选厂商不可操作，更换厂商清空已选项 | Jira 后台配置第1项、A01、A07 |
| AC-04 | 只提供该厂商游戏，按游戏类型分组，可按名称搜索；可多选、可留空 | Jira 后台配置第2项、A02、A08 |
| AC-05 | 单款或整类排除的游戏不可推荐；先推荐后排除时自动从推荐项移除 | Jira 后台配置第3项、A04—A06 |
| AC-06 | 前台对应厂商榜按后台选择顺序展示推荐游戏；无推荐项则隐藏整个区块 | Jira 共用规则、A03、A08 |
| AC-07 | 活动进行中修改推荐配置，在次一统计日00:00生效 | Jira 共用规则 |

## 与既有排行的关系

[ISOP-2091既有设计](../history/archived-20261005/ISOP-2091/design.md)及[已有决定](../history/archived-20261005/ISOP-2091/questions.md)记录：各厂商独立按有效投注排名，排除项不计入；同分按达到分数的结算时间排序、不并列；未达门槛不显示名次与奖励；按GMT+8统计日处理，配置次日生效且不回溯。2230未提出替换这些计算、门槛、派奖规则，回归时保留原预期。

2091曾把More Games不展示排除项列为未采纳建议。2230现在明确了“推荐游戏”的排除联动，应按本单验收；不能反推其他所有游戏入口也有同一新规则。页面仅显示前100名，也不等于统计、奖励配置或派奖范围被限制为100名。

上述2091内容来自2026-09-21、2026-09-29的本地历史记录，本次只作规则比对，未重新刷新2091 Jira或重测历史缺陷。旧结果不转为本单通过。

## 实施与测试安排

先核配置读写是否保留游戏顺序、厂商关联及当前／待生效版本，再核前台H5、App的Details、榜单与推荐区块。跨日验证需要同一活动变更前后两份配置及统计日证据，不能以保存成功代替次日生效。推荐配置无需触发实际投注来证明展示；排行与派奖回归优先使用已有独立样本。

本次未刷新正式接口契约、未登录业务后台、未保存原型配置，未创建执行计划或自动化门禁。详细准备见[测试重点](test-cases.md)。
