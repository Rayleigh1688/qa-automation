### ISOP-2092-C01：查看三组指标及说明提示

**前置条件：**

- 使用具有首页看板查看权限的测试账号，已登记环境与部署版本。
- 按已读Jira §二准备指标名称、分组和提示文案清单；未取得完整清单时先补齐，不凭当前页面反推预期。

**操作步骤：**

1. 打开后台首页，依次查看会员/充值、投注/GGR、游戏GGR三组指标。
2. 逐项对照字段清单，检查名称、所属分组和显示内容。
3. 逐个悬停有说明入口的指标，核对提示文案与该指标的统计口径。

**预期结果：**

- 三组指标与Jira §二清单一致，无遗漏、重复或分组错误；游戏GGR包含规定的7类游戏。
- 提示对应当前指标，内容与已确认口径一致；涉及未决计算规则的内容转对应问题核验。
- 本条检查展示和说明；金额是否正确由C05—C08分别核对。

### ISOP-2092-C02：切换单日和快捷日期，核对注册人数

**前置条件：**

- 以UTC+8准备可追溯的注册记录，覆盖日、周、月的起止边界及区间外记录。
- 记录实际点击日期；分别准备普通日期、周一及月初场景，可用经确认的测试时钟或样本回放，不修改系统时间。
- 已取得日期查询契约，能把请求参数还原成UTC+8业务区间。

**操作步骤：**

1. 选择一个有已知注册记录的单日，记录筛选日期、请求区间及注册人数。
2. 依次点击今日、昨日、本周、上周、本月、上月，逐组记录点击日期和实际请求区间。
3. 用独立注册清单统计各区间人数，核对边界记录的归属。
4. 在周一及月初场景重复相关快捷项，检查跨周、跨月结果。

**预期结果：**

- 单日以UTC+8划分；今日、昨日分别对应点击当天和前一天。
- 周区间按周一至周日、月区间按月初至月末定位，具体取数范围符合Jira §三。
- 注册人数等于所选区间内注册用户数，区间外记录不计入；请求区间和页面日期一致。
- 图表扩展窗口另见C04，不将图表日期当成指标卡筛选日期。

**待确认：**

### ISOP-2092-C03：查询自定义日期的89、90、91天边界

**前置条件：**

- 在同一UTC+8基准下准备89天、90天、91天三组窗口。
- 先记录日期控件及接口的端点、天数计算方式，再列明每组具体起止日期；不能混用自然日数量和时间戳差值。端点语义未核定时暂不判定边界结果。

**操作步骤：**

1. 选择89天窗口并查询，保存控件日期及请求参数。
2. 依次选择90天、91天窗口，分别尝试查询。
3. 核对各组页面处理和实际发出的请求；接口映射完成后，补核同组参数的服务端处理。

**预期结果：**

- 89天窗口满足“小于90天”，可作为有效查询区间。
- 90天、91天窗口均不满足限制，不应成功作为有效窗口返回业务统计。
- 界面拦截与接口处理分开记录；尚无错误码或提示文案契约，不自行指定文案。

### ISOP-2092-C04：查看快捷日期对应的图表窗口

**前置条件：**

- 本条仅保留设计，既有图表不执行决定仍有效；恢复执行须另有明确安排。
- 准备多个点击日期，包含周一、月初和普通日期；列出六个快捷项。
- Q-01尚未明确上周、上月的确切端点及六个自然月超过180天的处理。

**操作步骤：**

1. 在执行范围开放且Q-01补齐后，登记本组点击日期及对应的已确认日期推演表。
2. 依次选择六个快捷项，打开图表，记录起止日期、粒度和周期数量。
3. 更换点击日期重复查询，分别核对日项、上周和上月。
4. 使用覆盖超过180天的六个自然月样本，核对月粒度限制。

**预期结果：**

- 日期推演以当前点击日期为基准，不能固定为某个历史示例日期。
- 日项默认7天；其具体日期与已确认的日期推演表对应。
- 上周、上月端点及月粒度180天限制按Q-01答复验收，当前不自行推算为已确认预期。
- Q-01未答复且执行范围未开放时，保留BLOCKED，不记PASS。

**待确认：**

[Q-01](questions.md#q-01)：图表端点及180天限制；既有图表执行范围尚未开放。

<a id="c05"></a>
### ISOP-2092-C05：区分首充当天复充与历史会员再充值

**前置条件：**

- 下列金额仅为隔离样本设计，使用已存在且可追溯的Completed订单，记录注册时间、订单时间、gt及首次充值时间。
- 会员A：D1注册，D1首充100（gt=1），同日再充20和30（gt!=1），D2再充40。
- 会员B：D1之前已首充，D1再充60（gt!=1）。
- 会员C：D2注册，D2首充200（gt=1），同日再充70（gt!=1）。
- 统计窗口内其他订单需可独立剔分；充值金额字段和gt映射先核验。

**操作步骤：**

1. 从注册及订单清单确认每名会员注册后的第一笔Completed充值。
2. 分别查询D1、D2，核对复充人数、金额及纳入订单。
3. 查询D1至D2，对照每日分类结果累加值。
4. 对比历史首充会员B及会员A在D2的订单，检查是否被错误纳入复充。

**预期结果：**

- 首充为注册后的第一笔Completed充值（gt=1）；复充须同时满足gt!=1且首次充值时间为统计当日。
- 仅就上述样本贡献：D1复充1人、金额50；D2复充1人、金额70。A的两笔同日复充不重复计人数。
- D1至D2按每日分类累加，复充人数2、金额120；不按整个查询区间重新定义首充人群。
- A在D2的40和B在D1的60均不计复充；首充100、200也不计复充金额。

**待确认：**

Q-02规则已解决；[字段映射](questions.md#q-02)仍待核验。

### ISOP-2092-C06：对比单日与跨日人数及ARPU

**前置条件：**

- 会员A在D1多次登录、D2再次登录；会员B仅在D1登录，会员C仅在D2登录。
- 准备对应两日可核对的充值记录及ARPU计算所需金额来源；其他会员贡献可独立核对。
- Q-03尚未明确跨日ARPU是否展示及分母口径。

**操作步骤：**

1. 分别查询D1、D2，核对单日登录人数及ARPU展示。
2. 查询D1至D2，记录登录人数、ARPU及其他依赖跨日人数的指标。
3. 列出每日人数累加4与区间去重3两种候选计算，待Q-03答复后只采用确认的口径对账。

**预期结果：**

- 单日登录按会员去重：上述样本D1、D2各贡献2人，A同日多次登录只计1人。
- 跨日是否显示“--”、是否计算ARPU及其分母依Q-03，不能把4或3直接选作已确认预期。
- 其他依赖跨日人数的指标也按明确规则核对；只完成单日观察不能将整条BLOCKED改为PASS。

**待确认：**

[Q-03](questions.md#q-03)：跨日人数及ARPU展示、分母与去重规则。

<a id="c07"></a>
### ISOP-2092-C07：核对普通、免费旋转和奖池派彩及GGR

**前置条件：**

- 准备普通注单、免费旋转（FS）、Jackpot三类可追溯记录，覆盖不同bet_type及7类游戏的适用样本。
- 保存同一统计窗口的原始注单、jp_winning及分类清单，另备结果精确为0的样本。
- 回推派彩所需字段、GGR字段与正负号由Q-04核验；精度及汇总顺序由Q-06核验。

**操作步骤：**

1. 查询同一窗口的总派彩、总GGR和各类游戏GGR。
2. 按核定字段独立回推注单派彩，核对普通及FS记录是否纳入，再加上jp_winning总和。
3. 对照原始注单逐项核对总GGR和各类GGR，保存来源及计算明细。
4. 查询精确为0和非零样本，核对金额显示；舍入边界样本待Q-06补齐后执行。

**预期结果：**

- 总派彩包含普通注单、FS和Jackpot；注单回推不按bet_type排除记录，再加jp_winning总和，不使用net_amount回推。
- GGR字段和正负号以Q-04核验结果为准；接口内部公式相等不能替代源单对账。
- 显示值为0时展示整数0，不带小数点；非零结果显示两位小数，具体舍入和先汇总还是先舍入按Q-06。
- 字段或舍入规则未补齐时，保留对应未验证项，整条仍为BLOCKED。

**待确认：**

[Q-04](questions.md#q-04)：派彩/GGR字段及正负号；[Q-06](questions.md#q-06)：舍入及汇总顺序。

<a id="c08"></a>
### ISOP-2092-C08：核对充提差、投充比及零值显示

**前置条件：**

- 按Q-05核定的字段与订单范围，准备同一窗口内可独立重算的充值、提现、有效投注记录。
- 样本A：充值100、提现40、有效投注250；样本B：充值100、提现100、有效投注0。
- 样本C：充值0、有效投注非0，用于零分母；另备除法结果超过两位小数的样本。
- 上述数字为计算示例，不代表环境已有数据或真实资金操作授权。

**操作步骤：**

1. 分别查询A、B窗口，从订单清单重算充值、提现和有效投注。
2. 核对充提差和投充比的计算值及页面显示。
3. Q-06确认后查询C及多位小数样本，核对零分母表现、舍入方式和处理顺序。

**预期结果：**

- 充提差=充值−提现，投充比=有效投注÷充值；字段及纳入记录范围按Q-05。
- 样本A充提差为60，投充比计算值为2.5；比例单位及页面格式需与交付字段说明对应，不擅自转换为百分号。
- 样本B充提差和投充比均为0，显示整数0，不带小数点；非零结果按既有决定保留两位小数。
- 样本C不能把“显示值为0”的规则套成零分母预期；零分母及多位小数处理依Q-06，未确认不判PASS。

**待确认：**

[Q-05](questions.md#q-05)：金额字段及统计范围；[Q-06](questions.md#q-06)：零分母和舍入。
