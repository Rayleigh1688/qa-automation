## 验收依据

下表整理来源中明确的规则；推荐的可靠性/权限场景在用例中标示为测试设计。有歧义的部分以问题编号关联，不把建议当成已批准需求。

| 验收编号 | 业务预期 |
| --- | --- |
| AC-01 | 以有效投注×返利率计算，非亏损返利，不分VIP；单一规则/会员/日封顶，0不限；单日有效投注严格超过活动级门槛才派发，无每日总返利封顶。 |
| AC-02 | 指定游戏优先于游戏类型，一注只命中一条，未配置不返；7类 Slots/Live/Table/Arcade/Bingo/Fishing/Sports；类型及游戏规则均有返利率、上限、打码倍数、状态，可增删覆盖层。 |
| AC-03 | T+1 04:00 批次结算前一日，自动进入奖金余额，无需领取；奖金无过期、不作废。 |
| AC-04 | 派发账变和流水按游戏类型分笔；3类参与各产生3笔。打码要求为各类实际返利×倍数之和；未达标不可提，达标解锁；沿用流水场馆/游戏限制，打码产生的投注不再生返利。 |
| AC-05 | 客户端弹窗只是到账通知：Congratulations! You received Cashback Bonus!；不聚合为手动领取流程。 |
| AC-06 | 报表每会员每日一笔；筛选账号、UID、手机、VIP、游戏类型、结算时间；统计去重人数/总有效投注/总返利；列表、按类型明细与CSV按下述字段清单。 |

## 报表字段清单

- 列表：序号 / 玩家账号 / UID / 手机号 / VIP等级 / 统计日期 / 有效投注金额 / 流水返利金额 / 打码要求 / 结算时间 / 明细。
- 类型明细：游戏类型 / 有效投注额 / 返利率 / 返利金额（封顶前） / 返利上限 / 实派返利金额（已封顶标示） / 打码倍数 / 该类型打码要求。
- CSV字段等于列表；明细按钮的导出表达以接口契约补齐，不擅自增加隐藏明细列。
- 活动配置：运营管理→活动列表→投注返利(ID32)→三步配置（基础配置/返利率配置/派发条件与弹窗）；后台原型保存不落地。
