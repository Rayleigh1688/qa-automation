### 两处接口的已知契约与缺口

来源：本机backend_api仍为`ca3c1c28af6ad5a4b416b60aeecb020279da4e9a`、工作区干净；未联网拉取远端。两份Bruno文档为`POST /admin/record/bet`和`POST /admin/record/game`。以下是文档契约，不是当前FAT实测结论；执行编码沿用项目后台CBOR规范。

| 条件 | 已核对契约 | 完整验收仍需核对 |
| --- | --- | --- |
| 时间范围 | page/page_size必填；至少一组投注start_time/end_time或结算settle_start_time/settle_end_time，均int64毫秒 | 非体育实际扩窗、含端点、同时传两组的作用、缺失/反向/超限输入处理；前端31天限制不能自动当作API拒绝契约 |
| 体育切表 | game_type=4或pagcor_game_type=sports_betting；结算不选体育时主表排除体育 | 文档仍省略“仅结算查询”条件；R31必须分别覆盖两种体育选择字段和投注/结算组合。两个分类字段冲突时的优先级未定义，不自行定产品FAIL |
| 线路/时区 | node=1查1，node=2查0/2，不传查全部；接口参数表无独立timezone字段 | 不凭UI时区选项新增请求参数；客户端应先转换绝对毫秒，结合人工UI核对。历史node=0及非法node行为未验 |
| 类型筛选 | 请求order_type为普通/FS/JP/红利；请求bet_type是online/onsite | 响应及源表bet_type却是数值注单类型；不得直接将源表bet_type复制为请求bet_type。源表已观察到0值，实际语义未定义 |
| 状态 | state为字符串，status为整数且建议优先state；源表0未结算、1已结算、2取消、3无效 | 部分结算/退款表达及同时传state/status的优先级未提供；取消样本可盘点但不能由注释推断所有状态规则 |
| 明细金额 | 响应net_amount是原始net_amount取反；payout_amount=原始net_amount+bet_amount | 此映射仅确认这两处接口文档，不推广到其他报表。独立对账需对源表金额使用Decimal，不能拿响应net_amount直接加投注推算派彩 |
| 分页汇总 | data.t总记录数、s当前页数、d明细、fd参数；a.subtotal当前页、a.total全筛选；金额字段bet_amount/valid_bet_amount/grand_inc/ggr及order_count | 要有独立样本集合核对过滤、分页与合计；grand_inc与明细payout_amount的实际聚合及去重需实测，不能只比两个共用查询逻辑的接口 |
| 体育独立来源 | 当前FAT可读orders两表为InnoDB、settle_time为bigint；文档称Doris GameRecordSportCopy为datetime | 未取得两者映射、同步截止点、去重键或Doris时间精度。相同响应不能证明切表；MySQL中无对应元数据不能证明Doris表不存在 |

### 本次有界样本盘点

使用本机`.env.fat`只读连接；每表`prefix='fat'`、按created_at倒序最多5000条，仅读取类型/状态/时间等汇总，无账号、手机号或订单标识。主表返回5000条、体育候选表6条。跨日按UTC+8计算且排除settle_time=0，避免把未结算计成跨日；本批与首轮500条抽样及时间不同，不直接比较数量变化。

| 样本条件 | 本次观察 | 对用例的影响 |
| --- | --- | --- |
| 非体育跨日/延迟 | 已结算跨日8条，含1条结算与投注相差超过24小时；分类为3 | R02/R03/R06有新候选；需按目标S/E计算是否真正处在扩窗之外，超过24小时本身不等于本阶段窗口外遗漏 |
| 取消状态 | 发现1条state=2、node=1、普通注单 | R24取消分支不再说“没有候选”；部分结算、退款、无效及前后状态快照仍缺 |
| 体育长周期 | 6条均node=2、普通注单，3条已结算且同日、3条未结算；已结算无超过24小时延迟 | R07/R31的长周期/跨月来源证明仍缺，不能用同日体育或空结果替代 |
| 线路与类型 | 有node=1/2和普通/FS/JP；未发现node=0，另有4条源表bet_type=0 | R13历史归属仍缺；R14可准备1/2基本分支，不能声称覆盖历史0；未知类型0不擅自归为普通 |
| 毫秒端点/迁移 | 有毫秒时间值，但本次未定位完整自然日末端或重结算前后快照 | 普通含端点可围绕现有记录构造查询S/E，无须改库；整日最后999毫秒、扩窗全部端点与R25迁移仍需对应证据 |

未在本次有界样本出现不代表全库不存在；单次当前记录不能证明重结算过程。独立对账还需在本地私有证据中建立业务键映射和一致截止点，当前匿名汇总不是可直接执行的完整预期集。
