<a id="c01"></a>
### ISOP-2091-C01：每厂商独立排名

**前置条件：**

- A厂商会员X有效投注1000、Y500；
- B厂商X100、Y900，均高于各自门槛且无并列

**操作步骤：**

1. 分别查询两个厂商榜单，并准备同一会员在两个榜单得奖

**预期结果：**

- A为X在Y前，B为Y在X前；
- 一笔注单只归属一个厂商；
- 同一会员可在多个厂商榜同时得奖

**待确认：**

接口/样本待核

<a id="c02"></a>
### ISOP-2091-C02：排除游戏类型与指定游戏

**前置条件：**

- 配置排除一个游戏类型和一款指定游戏；
- 另准备该类型新上架游戏及合格游戏

**操作步骤：**

1. 分别投注/查询排除项、合格项和新上架项的累计

**预期结果：**

- 排除类型包含之后新上架的该类型游戏；
- 指定游戏只排除该款；
- 合格游戏计入；
- 不得排除厂商全部游戏

**待确认：**

接口/样本待核

<a id="c03"></a>
### ISOP-2091-C03：排名区间校验

**前置条件：**

- 排名人数100，准备1、11—50、51—100及缺口、重叠、超出100的配置

**操作步骤：**

1. 在四步向导逐行新增、删除和修改结束名次

**预期结果：**

- 首列从1开始连续；
- 起始名次自动接续；
- 不可重叠/跳号；
- 最后结束名次必须等于排名人数；
- 非法时不能进入下一步

**待确认：**

原型与实现待核

<a id="c04"></a>
### ISOP-2091-C04：门槛、同分、名额与多榜得奖

**前置条件：**

- 每个厂商设置不同门槛，准备低于、等于门槛及同分会员；
- 奖励名额大于达标人数

**操作步骤：**

1. 按结算时间制造同分，查询榜单和获奖名单

**预期结果：**

- 有效投注≥该厂商门槛才排名；
- 门槛0表示不限；
- 同分按达到该分数的结算时间先后且不并列；
- 不足名额不递补；
- 同会员可多榜得奖

**待确认：**

接口/样本待核

<a id="c05"></a>
### ISOP-2091-C05：三类奖品与流水

**前置条件：**

- 各准备现金、Free Spin、商城币奖励；
- 配置Free Spin厂商/游戏、次数、投注额、有效期、提款边界和全活动流水倍数

**操作步骤：**

1. 查询派发、现金/FS/商城币资产、流水和报表显示

**预期结果：**

- 现金为每人金额且流水=奖金×倍数；
- FS为指定游戏次数且流水=赢得金额×倍数；
- 商城币为每人币数且无流水；
- 报表单位不混淆

**待确认：**

奖励/资产接口待核

<a id="c06"></a>
### ISOP-2091-C06：周期结算与配置变更

**前置条件：**

- 准备跨GMT+8日边界注单：23:50下注、00:10结算；
- 周期中修改厂商/排除项/奖励/流水

**操作步骤：**

1. 保存修改后核当日与次日累计、最终名次和派发

**预期结果：**

- 统计日按结算时间归属；
- 每日00:00—23:59:59 GMT+8；
- 隔日04:30自动派发；
- 保存后次日00:00生效；
- 当日按原配置，已结算日期不回溯；
- 保存提示生效时间

**待确认：**

调度/版本接口待核

<a id="c07"></a>
### ISOP-2091-C07：四步后台配置与保存校验

**前置条件：**

- 准备至少两家厂商、排除类型/游戏、奖励区间和基础配置

**操作步骤：**

1. 依次操作基础配置、厂商配置、排名奖励、派发文案；
2. 验证重复厂商、全排除、空奖励、文案超长等错误

**预期结果：**

- 活动ID34/类型正确；
- 至少保留1家厂商；
- 厂商不可重复；
- 门槛≥0；
- 排除项树状行为正确；
- 必填和范围错误阻止下一步/保存

**待确认：**

原型与实现待核

<a id="c08"></a>
### ISOP-2091-C08：报表与前台榜单展示

**前置条件：**

- 准备多个厂商、历史统计日、不同奖励类型及未达门槛会员

**操作步骤：**

1. 查看活动列表报表弹窗、前台厂商分页、前三名、我的名次、History、Reward Details、Standard T&C、More Games

**预期结果：**

- 报表按一行一人/厂商/统计日，字段和统计卡齐全；
- 前台显示遮罩昵称、投注、奖励和厂商顺序；
- History只看前一日起历史；
- 未达门槛按修订稿展示；
- Cashback文案问题不能作为通过

**待确认：**

[Q-04](questions.md#q-04)；设计稿修订待核

<a id="c09"></a>
### ISOP-2091-C09：派发幂等与通知

**前置条件：**

- 准备可派发、失败和重跑排程样本；
- 同一会员/厂商/统计日仅一条资格

**操作步骤：**

1. 执行或观察隔日04:30派发及重跑；
2. 查询资产、派发状态和通知

**预期结果：**

- 活动最后一天也正常派发；
- 重跑不重复派发；
- 失败不发“已到账”通知；
- 成功按后台弹窗文案通知；
- 派发时间固定且不可修改

**待确认：**

调度/通知契约待核
