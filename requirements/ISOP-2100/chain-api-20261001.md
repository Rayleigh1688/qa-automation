## 候选接口顺序

| 步骤 | API | 关键输入与验证 |
| --- | --- | --- |
| 分配两名测试会员号码 | 管理 `POST /admin/member/list` | 已有工具先验证手机号精确筛选，再从FAT专属游标找未注册号码；A_new和M_new分别记录，不复用现有代理/会员 |
| 注册A_new | 客户端 `POST /member/sms` → `POST /member/register` | 短信取得本次otp_id；注册传otp_id、code、password。首个账号不带邀请关系。现有RegistrationOperations已实现，不需复制协议栈 |
| 核申请资格 | 客户端 `GET /member/detail`；`GET /member/agency/audit/results` | 同一新会员token；看can_apply_agency、当前审核状态。契约没有明确KYC门槛，不能假定未KYC也一定可申请 |
| 发起代理申请 | 客户端 `POST /member/agency/apply` | 文档无业务参数，使用当前新会员身份；返回成功不等于已成为代理 |
| 按实际要求补申请资料 | 客户端 `GET /member/agency/problem/list`；`POST /member/agency/apply/material` | 问题返回ty、长度/数值范围、required；资料示例有email、fb_username、problem1—4、video_link。资料是否必要及提交顺序须按实际返回状态核验，不把示例固定值硬编码 |
| 定位本轮申请并审核 | 代理管理 `GET /admin/agency/audit/list` → `POST /admin/agency/audit/agree` | 列表page/page_size及本轮uid精确筛选，取申请记录id；同意传该id，不能将会员UID直接代入，也不能取待审第一行 |
| 核代理已成立及邀请码 | 管理 `GET /admin/superior/one?uid=...`；代理管理 `GET /admin/agency/list` | superior文档state=2表示通过；代理列表读取该会员对应invite_code，核代理启用状态。再次核客户端审核结果并用已验证Code Login登录新代理 |
| 注册直属M_new | 客户端 `POST /member/invite/code/check`；`POST /member/sms` → `POST /member/register` | 校验从新代理读取的invite_code，再注册新会员；注册工具支持REGISTER_INVITE_CODE。REGISTER_I对应普通好友邀请，本链路不混填 |
| 核直属与报表 | 客户端 `GET /member/detail`；代理 `GET /agency/member/list`、`GET /agency/profile`；管理 `GET /admin/reports/agency` | M_new的parent_uid应指向A_new，代理列表包含M_new；新代理累计/当日注册人数按基线增量核对，同日期两端一致。必要时只读DB复核关系，不通过转线修补 |

## 首次执行仍须核实的契约

1. **代理审核服务地址与权限。** FB列表/编辑等使用`angency`，审核同意又使用`admin_url`；存在历史独立代理管理域名。必须先fresh登录并以只读审核列表/权限验证当前FAT路由，不机械替换域名，不把主管理后台可登录当成代理审批已授权可用。
2. **审批仍需哪些字段。** 同意契约只有id标必填，settle_type、acc_type、google_code标可选。停佣金不意味着自动通过或这些字段已删除；仅按当前服务实际契约提交，本链路不修改全局佣金配置。若需要审核码，使用当前环境审批TOTP机制，不把固定后台登录码当审批码。
3. **邀请码到直属关系的映射。** 注册文档只把invite_code写作“推荐码”，i写作“邀请好友”，未说明invite_code如何生成parent_uid及两者优先级。代理列表存在invite_code字段，但是否可直接用于当前注册须实际校验。不能因传了码或注册成功就认定是代理下线，必须核M_new的parent_uid与A_new会员列表两处。
4. **申请资格与资料。** can_apply_agency只说明当前可否申请，问题列表required说明问题是否必填，均未定义KYC资格公式；没有证据时不宣称申请无前置。10-01契约搜索未找到可替代该流程的直接“新增代理”API；10-02补查已找到管理后台直接转代理的产品路径，见上方来源。后台员工新增和会员“顶级用户”标识不等于业务代理。

## 最小链路的通过条件

- 只使用本轮创建的A_new、M_new及对应申请id，每步同时核HTTP、解码结果、业务状态及实体字段；中途失败保留结果并停止后续依赖写入。
- A_new审批后能登录代理后台；记录注册M_new前的直属列表及累计/当日人数基线。
- M_new注册后当前parent_uid=A_new，代理会员列表精确命中该会员，A_new自己不能算作下线；首页和管理代理统计按同一日期核人数增量，并记录统计更新时间，沿用户认可的一小时容差复核。
- 本段验证注册与归属；没有存款/投注等活动时，会员日统计依其非零筛选规则可以没有该会员行，不能为了让报表出行制造资金记录。若注册自动产生奖励，按实际事件保留并核来源，不能先假设金额全为零。
- 后续若扩展金额闭环，再接独立的充值/投注/彩金源单与报表对账。佣金计算/派发不加入本条新账号链路；2100已有其他失败不会因本链路通过自动关闭。
