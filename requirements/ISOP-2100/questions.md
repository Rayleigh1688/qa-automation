<a id="q-01"></a>
### Q-01：本次修改哪些页面？

**已明确。** 正文§3明确五处：代理首页、会员列表、会员日统计；管理端代理统计、会员日统计个人统计页。佣金页/佣金账变/礼金页移除，代理佣金计算和派发停止，代理日统计不提供总佣金。无需再泛问范围；停发执行边界见Q-06。

<a id="q-02"></a>
### Q-02：正式接口与数据源是否准备好？

**开发核验。** FB已有`/agency/profile`、`/agency/member/list`、`/admin/reports/agency`及`/admin/reports/member`系列；现有文档仍是旧字段，未检得建议新增的`/agency/home/stat`、`/agency/report/member`系列契约。需核新增字段、代理历史维度、列表/明细/导出共用过滤、FAT真实聚合数据及账号。接口缺口不等于产品未定义；不照抄评论中的建议URL当已部署。无数据已明确0／P 0.00、上线移除星号和示范提示；接口故障不能当无数据。

<a id="q-03"></a>
### Q-03：金额公式与统计时间还有哪些歧义？

**产品确认＋开发字段核验。** 正文已明确有效投注取已结算`bet_type=1,3`的`valid_bet_amount`，NGR=GGR−Bonus，Bonus不含邀请好友佣金；人数区间去重，首存是人生第一笔成功存款。

**最重要的矛盾：** GGR要求平台赢为正，却写“不分bet_type的net_amount加总＋jp_winning”，未说明该net_amount是哪张表、哪个视角。请以玩家净赢100、另中JP20的样本确认平台GGR应如何取负，JP是否已含于net，避免符号反向或重复计算。既有2092派彩公式不能直接充当2100 GGR决定。

**需补齐：** 存款、提款、彩金按提交/到账/出款/派发哪个时间入日，金额对应哪个字段；跨日成功和冲正如何归属。显示两位已明确，舍入/截断及先汇总后处理仍需统一；人均首存/注充率需确认分子分母及分母为零显示（原型可能显示“-”）。G4应明确只比较共有指标，累计会员数不受日期影响，不能等同“有活动会员”人数。

<a id="q-04"></a>
### Q-04：会员转代理后，历史数据谁能看？

**基本权限已明确；转移边界待确认。** 已明确仅登录代理直属下线、范围由服务端身份决定；所属代理与邀请人不是一回事。管理端历史数据按当时代理归属已明确。

**剩余场景：** 会员9月15日从A转B，查询9月整月时A/B各看哪些日期？旧代理能否查看已不在当前名下会员的历史明细？当天转移按事件时点拆分还是整日快照？需使“当前直属下线”权限与“历史归属”规则一致，避免拿当前parent_uid回算全部历史。

<a id="q-05"></a>
### Q-05：更新周期与跨页对账何时算一致？

**开发核验；验收时点待明确。** G5明确当日至少每小时更新；§6另建议会员每5分钟、代理每10分钟、次日02:00/03:00分别重算。这些周期可以兼容，但两层异步更新期间不一定即时相等。

**需要明确：** 正式采用的排程、数据截止时间/可接受延迟及对账时点；会员02:00重算后代理03:00刷新前是否允许短时不同；补跑与指定日期/对象重算能否覆盖迟到更正数据、是否会影响派发。不得用“同源”自动判定同一时刻一致。

<a id="q-06"></a>
### Q-06：代理佣金从何时停，存量怎么处理？

**产品确认。** 正文§3已要求停止全部代理佣金计算、派发，不是单纯隐藏菜单。

**需要明确：** 停止生效时间，已算未发/审核中/历史结余如何处理，旧入口及手动/定时/重试任务如何阻止继续发放；确认不连带停止好友邀请佣金。原型仍显示“每月结算”和费率查询，其保留或删除也应随停佣金决定统一。本轮不执行停发或配置操作。

<a id="q-07"></a>
### Q-07：会员列表默认全量还是当日，保留哪些筛选？

**正文内部及原型不一致。** §5.3同时写“默认查询当日数据”和“进页即看到完整名单”；当前原型注册日期为空、显示60条包含历史注册的示范会员。正文仍列代理账号/代理手机筛选，原型已删除，评论17358也建议删除但未作为正文决定。

**建议待确认：** 默认不限制注册日期，展示本人全部直属会员；代理端移除代理账号/手机筛选。评论称模糊搜索最多命中50个UID且建议维持，需明确采用完整账号精确搜，还是保证模糊搜索全部结果，不能与“导出全部符合条件”冲突。

<a id="q-08"></a>
### Q-08：查询上限是否正式定为90天？

**产品确认。** G6仍写“90天暂定，见第八节第7点”，但当前正文止于§6；G5及历史归属也引用已不存在的第八节。评论提到旧HomeBI60天、管理报表90天。请正式确定统一上限、起止日期是否含首尾、哪些列表/明细/导出适用，补齐或删除失效引用。不把旧60天接口限制当新需求。

## 已有规则，不重复询问

- 五处页面及四组16指标；仅直属代理关系，禁止用邀请链替代。
- GMT+8、00:00日切、周一周起始；累计会员不随日期变化，存提/投注等人数按区间去重。
- G2服务端隐藏完整手机、Email、IP、备注/标签，姓名每段仅首字，手机前4后3；列表、统计、明细和导出均需覆盖。管理端保持原隐私规则。
- G7导出全部筛选结果，非当页；会员统计当页小计/全量总计，逐日明细加总等于会员主表；全局排序。
- 代理统计新增6列、账号下钻带代理和日期；管理会员个人统计加所属代理精确筛选/列/导出字段，邀请统计不改。
