## 问题详情

<a id="q-01"></a>
### Q-01：站内信额外统计与目标字段是否移除

**场景：** Jira正文第15项要求在`MessageListV2`注释`trigger_person`、`maintainer`外，另请确认会员端是否需要`total_send_count`、`read_count`、`target_users`。

**需要确认：** 会员端是否使用上述3个字段；若不需要，开发是否已在`MessageListV2`一并移除，QA按最终字段清单断言。

**答复：** 待确认。

<a id="q-02"></a>
### Q-02：`Game`结构体改动方式与缓存影响

**场景：** 第4项`/member/game/list/recommended`建议在回传前清空字段或直接将`Game`结构体的`updated_name`、`updated_uid` json tag改为`"-"`（可同时覆盖第9项）。

**需要确认：** 实际采用哪种改法；若修改json tag，是否已确认`Game`结构不用于写缓存或后台序列化（避免影响A07后台显示）。

**答复：** 待确认。

<a id="q-03"></a>
### Q-03：`release`合并与FAT部署就绪情况

**场景：** Jira 状态为`已修復`，QA 子任务仍`待办`，两单无修复链接或部署回执。[FB 提交核对](design.md#接口文档提交核对)仅取得 Bruno 文档变更。

**需要确认：** 取得 member、promotion、finance 的实际修复提交或合并记录，核对对应版本已部署 FAT。钱包密码响应清理及日志删除均需有实现证据，核对是否包含 `10cbcd5` 或等价改动。

**答复：** 待确认。

<a id="q-04"></a>
### Q-04：会员敏感数据范围及核验条件

**场景：** 第四部分标注“不是員工資料，但建議一起處理”，其中A05涉及后端日志检查，A06涉及三方账号登录分支。

**需要确认：** A05/A06是否作为本次上版阻塞验收项；FAT是否有可用三方登录测试账号，以及如何查阅后端日志确认无钱包密码哈希输出。

**答复：** 待确认。

<a id="q-05"></a>
### Q-05：原报告9支API回归范围

**场景：** 2375 Jira 正文提到原报告 9 支 API。[ISOP-2239 §003 的本地摘录](../history/archived-20261127/ISOP-2239/design.md#员工字段清理范围)有九条同类接口，八条与 2375 验收路径重叠，额外一条是 `/member/kyc/detail`。原 VAPT PDF 尚未复核。

**需要确认：** 确认原报告范围是否与摘录一致，以及是否纳入 `/member/kyc/detail` 的额外回归。

**答复：** 待确认。

<a id="q-06"></a>
### Q-06：活动列表请求契约

**场景：** Jira 提供会员端 `/promo/list` 路径与匿名验收要求。当前 Bruno `a36be1d` 和本地接口目录没有该路径的请求定义。

**需要确认：** 从当前会员端活动页请求或后端路由取得方法、请求参数、响应样本路径，确定一条匿名可见活动供验证。

**答复：** 待确认。

### Q-07：四品牌首页 v2 入口

**需要确认：** 按四个品牌记录实际域名、路径、查询参数及决定品牌路由的非认证请求头，提供能区分各品牌响应的样本。

**答复：** 待确认。
