## 问题详情

<a id="sg-q01"></a>
<a id="q-01"></a>
### Q-01：钱包版本和目标游戏编码

**场景：** 本期接drop ball pinoy；附件候选为`10022 Drop Ball`，实际PDF正文为单钱包2.6.2，文件名与版本日期存在差异。

**问题点：** 已读合同不能按文件名解释成双钱包，但正式接入基线和正文游戏名对应仍需冻结；厂商Live路由也不能覆盖Pagcor specialty game。

**需要确认：** 是否按实际SingleWallet 2.6.2接入10022，版本日期差异如何订正，drop ball pinoy与10022是否同款且采用什么平台分类映射？

**答复：** 待确认。由游戏后端与SG冻结合同、版本和编码，产品／合规确认分类，收到后记录答复人、日期和来源。

<a id="sg-q02"></a>
<a id="q-02"></a>
### Q-02：金额单位和换算

**场景：** 按PDF p21的DropBallLive示例进行投注；示例金额与余额变化注释存在[已核对矛盾](design.md#合同冲突与影响)。

**问题点：** 无法从该示例独立确定请求金额、响应余额及平台金额的换算，错误换算可能导致十倍或百倍扣款。

**需要确认：** 各金额字段实际单位和换算是什么，请提供包含投注、派彩和前后余额的独立可计算样本。

**答复：** 待确认。由SG、游戏后端与对账负责人裁决，收到后记录字段单位、样本、答复人、日期和来源。

<a id="sg-q03"></a>
<a id="q-03"></a>
### Q-03：JP字段落点和缺失值

**场景：** 一笔有奖池贡献的回调返回seed／contribution，另一笔可能缺少这些可选字段或返回零；另有当前总奖池查询。

**问题点：** 数据来源已明确，但平台落点、缺失与零的语义及贡献金额单位未冻结，不能用当前总奖池代替本笔贡献。

**需要确认：** seed／contribution落哪些平台字段或报表，缺失与零值如何区分，贡献如何与已确认金额单位对应？

**答复：** 待确认。由产品、游戏后端与SG确认消费规则，收到后记录答复人、日期和来源。

<a id="sg-q04"></a>
<a id="q-04"></a>
### Q-04：重复退款响应和去重动作

**场景：** 原成功投付被退款，厂商重复发送退款；退款引用原交易`transaction_id`。

**问题点：** PDF重复退款响应存在[合同冲突](design.md#合同冲突与影响)。只按交易号去重可能吞掉退款，投付与退款身份混用又可能重复加款。

**需要确认：** 重复退款采用p33返回退款金额还是p34错误3041，原投付与退款复用交易号时按什么动作身份分别去重？

**答复：** 待确认。由SG、游戏后端与对账负责人裁决，收到后记录响应合同、答复人、日期和来源。

<a id="sg-q05"></a>
<a id="q-05"></a>
### Q-05：JP通知范围和实际路由

**场景：** 若本期接JP中奖通知，厂商通知到达时，中奖金额可能已通过投付回调处理。

**问题点：** PDF正文与重试表的通知路由不同；通知与`win_amount`的入账责任也影响是否重复派彩。

**需要确认：** 本期是否包含JP中奖通知；如包含，采用`PrizeNotify`还是`JackpotNotify`，通知仅记录还是另承担入账？

**答复：** 待确认。产品先确认范围，SG订正合同，游戏后端确认入账责任，收到后记录答复人、日期和来源。
