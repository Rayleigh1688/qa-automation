## 用例详情

<a id="c01"></a>
### ISOP-2320-C01：活动Section映射与显示顺序

**前置条件：** 取得包含Section.id=12、13的首页板块配置；使用指定SIT交付版本或后续明确版本。

**操作步骤：**

1. 进入游戏列表，记录配置响应和页面顺序。
2. 逐项核对Section ID、标签和All Games/厂商Section相对位置。

**预期结果：** Section 13显示`1.3% + 2% RETURN`，Section 12显示`EXCLUSIVE`；顺序为All Games → RETURN → EXCLUSIVE → 厂商。父单截图中的1.5%不作为当前预期。

**待确认：** [Q-02](questions.md#q-02)：标签百分比是否动态配置。

<a id="c02"></a>
### ISOP-2320-C02：Section游戏清单与图片展示

**前置条件：** 两个Section各有可识别游戏及图片；有分类和厂商筛选的对照清单。

**操作步骤：**

1. 分别打开RETURN、EXCLUSIVE和厂商Section。
2. 按游戏标识核对每个清单成员、图片资源和一般游戏卡片展示。

**预期结果：** 每个Section展示其配置/接口返回的游戏和对应图片；不串组、不漏掉有效返回项，正常清单仍可操作。

**待确认：** [Q-01](questions.md#q-01)：清单成员是否还受活动资格配置过滤；[Q-03](questions.md#q-03)：默认排序依据。

<a id="c03"></a>
### ISOP-2320-C03：分类、活动选项与厂商互斥筛选

**前置条件：** 准备可在不同分类、RETURN/EXCLUSIVE和厂商中区分的游戏样本。

**操作步骤：**

1. 逐一选择分类、RETURN、EXCLUSIVE及一个厂商筛选。
2. 在每个筛选状态再选择另一类筛选，观察选中状态和返回清单。

**预期结果：** 分类筛选可用；RETURN、EXCLUSIVE与厂商筛选互斥，任一时刻仅保留符合互斥规则的筛选状态，游戏列表与选中状态一致。

**待确认：** —

<a id="c04"></a>
### ISOP-2320-C04：筛选切换、返回与直连状态

**前置条件：** 已知有效的Section/筛选路由状态及可直接访问的测试链接；至少两种可切换筛选。

**操作步骤：**

1. 在筛选间切换，进入游戏列表后返回。
2. 直接打开各筛选状态链接，并刷新/重新进入页面。
3. 记录筛选状态、列表成员及排序前后是否稳定。

**预期结果：** 页面选中状态、路由状态和游戏清单互相一致；返回及直连行为符合已确认设计，无旧筛选残留。

**待确认：** [Q-03](questions.md#q-03)：具体路由参数、返回保留规则和排序契约。

<a id="c05"></a>
### ISOP-2320-C05：配置、清单及图片异常恢复

**前置条件：** 可控测试环境能提供无配置、空清单、配置/清单读取失败、逾时和图片失败样本；正常游戏列表可作为对照。

**操作步骤：**

1. 分别触发缺配置、空数据、读取失败/逾时和图片资源失败。
2. 按页面提供的重试方式重试，随后恢复正常响应。
3. 检查异常区块和其他正常游戏清单的可操作性。

**预期结果：** 异常场景得到可理解的容错反馈；可重试场景可恢复；正常游戏列表仍可操作，不因单个Section失败而整体卡死。

**待确认：** [Q-04](questions.md#q-04)：错误反馈文案、逾时阈值及重试次数/间隔。

<a id="c06"></a>
### ISOP-2320-C06：登录登出后的游戏数据隔离

**前置条件：** 两个授权测试账号的可见游戏/筛选数据可区分；无真实个人资料。

**操作步骤：**

1. 账号A登录并打开活动Section，记录筛选和列表状态。
2. 登出后以账号B登录，重新打开相同入口。
3. 返回A账号复核，不重用B会话缓存。

**预期结果：** 不同账号间不残留错误的账号态、列表数据或筛选状态；显示与当前登录账号一致。

**待确认：** —

<a id="c07"></a>
### ISOP-2320-C07：游戏启动限制与退出返回

**前置条件：** 准备一款可正常启动游戏及一款处于现有限制条件下的游戏；明确进入前页面。

**操作步骤：**

1. 从RETURN、EXCLUSIVE和厂商筛选结果分别尝试启动游戏。
2. 覆盖现有禁止/限制条件下的启动行为。
3. 退出游戏并检查返回页面和筛选状态。

**预期结果：** 新入口遵守既有游戏启动限制，不绕过原有准入；退出回到进入前的合理页面，筛选/路由状态符合设计。

**待确认：** —

<a id="c08"></a>
### ISOP-2320-C08：横向及旋转后的布局和点击

**前置条件：** 手机/模拟器支持横屏；覆盖常规横向、较短横向视窗及旋转前后状态。

**操作步骤：**

1. 在横向及较短横向视窗打开游戏列表。
2. 旋转设备，在RETURN、EXCLUSIVE、厂商筛选及游戏卡片上执行点击。

**预期结果：** 内容无关键遮挡/溢出，筛选和游戏卡片可点击；旋转后布局与交互可用。

**待确认：** —

<a id="c09"></a>
### ISOP-2320-C09：Section成员与活动资格核对

**前置条件：** 产品/后端确认Section成员与当前Filplay活动配置的关联；提供当前活动版本、配置快照及有资格/无资格游戏样本。

**操作步骤：**

1. 独立核对Section 13/12成员与活动配置中的适用游戏。
2. 对照每个样本的活动资格来源，确认是否应出现在Section中。
3. 不执行投注、结算或派奖写入。

**预期结果：** 仅按确认后的配置关系核对展示资格；列表出现某游戏不等于已验证返利计算、活动资格或派奖正确。

**待确认：** [Q-01](questions.md#q-01)、[Q-02](questions.md#q-02)。
