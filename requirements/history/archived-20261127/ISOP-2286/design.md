# ISOP-2286：FILPLAY KYC调整设计

[设计](design.md) · [问题与决定](questions.md) · [测试重点](test-cases.md) · [W27增量扫描](../../../reviews/2026W27-20261028.md)

2026-10-28只读初评，待人工评审。两站各存一份KYC，由手机号关联，Filbet为主档、Filplay为副本；只有Filbet后台可以审核和修改KYC。正文已明确注册复用、提交受理顺序、双向同步、来源站发奖及封锁优先，尚需确认同步失败的收敛方式、注册查询故障及无Filbet账号的主档承载。本轮未提交KYC、注册、审核、封锁、发奖或执行业务查询。

## 明确规则

以下验收点来自[Jira ISOP-2286](https://alibaba-international.atlassian.net/browse/ISOP-2286)正文；与最新2123文字合读，不以旧本地用例的同UID假设覆盖新规则。

| 验收编号 | 规则 | 来源定位 |
| --- | --- | --- |
| AC-01 | Filbet存放全部KYC主档，包括尚无Filbet账号的人；这类记录不出现在Filbet会员列表。Filplay保存副本，两站按手机号关联、KYC保持一致 | §2机制／原则；2123前提明确两站账号独立、UID不必相同 |
| AC-02 | KYC审核只在Filbet后台操作，Filplay后台可查看全部KYC信息、不能审核；会员不能自行修改生日、性别、实名，后台修改仅在Filbet进行并同步 | §2原则 |
| AC-03 | 两站注册均先按手机号查既有KYC，找到即取得或绑定，找不到才新建；只有Filplay账号者后来注册Filbet时绑定既有主档、不另建KYC | §2同步情境、规则1 |
| AC-04 | 仅Filbet有账号时，其变更不同步到尚无账号的Filplay；该手机号注册Filplay时取得Filbet KYC。Filplay首次新建KYC后同步至Filbet；双方有账号时，审核、提交、封锁、后台修改、系统自动通过均同步；仅有Filplay账号时，Filbet主档的审核、提交、封锁、修改也同步到Filplay | §2原则／同步情境 |
| AC-05 | Filplay提交先交Filbet依序检查审核中、已通过、已封锁、证件被其他手机号使用；任一不通过即拒绝，并返回Filbet当前状态更新副本。仅全部通过且待送件或需重送时受理，两站同时改审核中 | §2提交受理检查 |
| AC-06 | 受理拒绝提示分别为“您的資料正在審核中”“您的身分驗證已完成”、现行封锁提示、“此證件已被使用，請聯繫客服”；已封锁时Filplay账号同步封锁。提交时连不上Filbet则不受理、保留已填资料，提示“系統忙碌，請稍後再送出” | §2提交受理检查；原文提示保持原值，客户端最终语言映射待核 |
| AC-07 | 同手机号近乎同时两站注册，以先到Filbet的记录为准，由Filbet通知覆盖Filplay副本；两站同时修改时封锁优先 | §2规则2、4 |
| AC-08 | Filplay系统动作改变KYC时先在Filplay执行，再同步Filbet；两站均检查NDRP，任一命中即封锁并同步另一站 | §2规则3、5 |
| AC-09 | KYC建立时记录来源站，KYC奖励和邀请奖励只由来源站发放；Filbet KYC审核列表新增“来源站”字段 | §2原则、规则7 |
| AC-10 | Filbet同步到Filplay时不同步门店，Filplay门店固定2；Filplay同步到Filbet时同步门店 | §2规则6 |
| AC-11 | 会员在两站都有钱包时两站会员列表均可出现。Filplay会员、存款、提款、全平台注单的门店列／筛选及Pagcor业务归属筛选只有门店2 | §1规则 |
| AC-12 | 门店域名跨门店及跨站唯一，违反时禁止保存并提示原因；游戏上下线／维护前二次确认标明站点及游戏名称或数量；注单及Pagcor旧品牌筛选移除但注单品牌列保留；单站导出限本站，总合报表合计；两类税收总合不分页、单站分页 | §1规则，与2123当前文字合读 |

## 暂不实现与待确认范围

正文将“Filplay注册时无法取得Filbet KYC（暂不实现）”标题划除，其下仍保留“确认中”、登录浏览、业务限制、重新查询四条方案。本次按标题的暂不实现标识记录为退出当前验收的方案，不能把这些段落编成已确认功能；实际注册查询失败怎么办见[Q-01](questions.md#q-01)。这不影响AC-06已经明确的“提交KYC时连接失败”处理，两种动作需分开。

正文“待讨论”明确保留无Filbet账号KYC及两站会员ID的存放方式；可追溯的查询／读回合同见[Q-02](questions.md#q-02)。同步时效、失败重试与并发版本检查属于需收口的实现合同，不能自行给出秒数或次数，见[Q-03](questions.md#q-03)。

上述为本轮影响登记，旧单正式资产尚未完成语义同步，不可据已有hash基线宣称已按新机制评审。旧单原有NOT_RUN及来源限制保持；源更新需要连同用例、CSV、XMind和证据记录一起重评。

## 接口与测试安排

先核按手机号识别主副档、站内会员ID映射、受理返回、同步事件／状态及来源站奖励读回能力，再准备仅Filbet、仅Filplay、双方都有、双方都无四类独立样本。查看与审核权限分别核页面入口和服务端结果；拒绝提交需查未新建审核单、未覆盖主档及副本按返回状态收敛。数据诊断只读，接口字段、状态枚举、版本及部署环境尚未核对，不推测API路径。

重复／并发、证件跨手机号唯一、NDRP与奖励的准备需隔离身份及既有资金记录。真实注册、KYC提交、后台修改和封锁执行前再按受控流程冻结对象和恢复边界；本次只形成[测试重点](test-cases.md)，未建正式卡片、CSV、执行计划或机器证据基线。
