# 新需求测试优化计划

更新：2026-09-11。试点为ISOP-2027。当前方向是**P0继续维护API与核心UI自动化；新需求API自动执行，UI由AI出用例、人工执行，暂不建设新需求UI自动化**。阶段1—3实现保留兼容；后续不安排新需求UI脚本和通用混合自动化扩建，旧结果和冗余代码已按用户授权清理。本文件据此收敛为当前计划，操作细节见[团队流程](team-testing.md)。

## 2026-09-14人机协作收敛建议

用户反馈：现有流程需要人检查多个文件、挑范围并拼命令，缺少测试平台的直接操作体验。建议以**Jira阶段+提测/文档事件驱动，同一执行器，集中可视化待办**为目标；先复用现有资产，不把迁移整个平台或再写一个复制逻辑的大脚本作为前提。本节保留实施前设计；当前实现见本文件第1—4项实施及统一命令手册。

| 事件 | 系统自动推进的内容 | 人需要处理的内容 |
| --- | --- | --- |
| 新需求/需求变更 | 拉取明确版本，AI整理接口能力预期、风险/用例、独立数据缺口；增量更新并保留原决定 | 回答业务歧义，确认有争议的范围/预期；已确认规则不重复问 |
| 接口文档提交 | 按Story与验收点映射变更，评估覆盖与受影响回归 | 无法归属或契约冲突时确认；文档提交不直接当部署完成 |
| 明确环境的提测/修复部署 | 校验版本、样本及既有授权；就绪的固定用例自动进入队列，暂停项保持 | 首次范围/新增写入/未知环境才确认；2022暂停优先于任何自动触发 |
| API执行/人工回填 | 保留逐轮证据，汇总API与人工结果、候选分类、下一步与待修复范围 | 看异常与业务取舍；只确认具体BUG建单，不逐条点击请求 |
| 进入UAT | 按用户团队约定登记FAT人工通过，保留来源；检查UAT适配与独立数据 | API失败与人工通过冲突时确认处置；不自动把API失败抹成通过 |
| 发布/关闭 | 关联实际版本、上线验证与关闭依据 | 确认发布/最终验收；Jira状态变化不等于生产部署完成 |

事件须以Story、环境、版本、计划hash、事件ID去重；过期消息不回退新状态，不跨环境借用样本。自动执行只消费已实现并已授权的计划，AI新生成的代码先本地校验和范围检查。部署标识缺失时沿用已批准测试例外并标未核验，不假装事件核验完成。

用户操作目标收敛为：打开一处需求列表，看到“可自动执行、缺资料、待人工验收、待BUG确认、待上线”，每行显示原因、下一步和报告。UI和CLI调用同一个编排服务；未来接平台也消费同一份计划/结果，避免两套状态和执行逻辑。多人分派、权限审计、共享服务部署成为明确需求时再选择平台承载方式。

当前`npm run qa:telegram`仍然只扫描/分析，不自动执行；`qa:requirement`已能按固定计划跑指定需求。**统一入口已由本轮新增的`npm run qa`提供**。此前建议实施顺序：先增加离线依赖诊断和统一状态/证据汇总；再把既有授权与版本绑定为可重复使用的执行策略、接入增量事件队列；最后用一个薄页面展示和处理队列，不再要求人记revision/参数。UAT运行适配是独立前置，不能靠改Jira状态绕过FAT限制。

本轮2027已重新执行历史风险项，详见[历史报告已清理；查看最新FAT报告](../requirements/ISOP-2027/test-report-2026-09-14.md)。CLI错误来自本机配置指向已退出的VS Code扩展版本；已更新本地codex_executable并验证可执行文件版本和所需参数。本次只是路径修复，后续扩展升级仍可能改变路径；可按[官方CLI安装说明](https://learn.chatgpt.com/docs/codex/cli)使用独立安装，并在统一诊断中检查实际路径。

恢复Telegram/Jira扫描与AI分析此前被自动审批拒绝，原因是发送消息/需求上下文给外部AI需要明确授权。2026-09-14用户随后明确授权该范围，现已恢复扫描操作；这不扩大测试、BUG提交或发群权限。实际扫描结果见当前交接。

## 当前结构

`requirements/<Story>/plan.json`维护用例、验收点、契约、参数集、actor、步骤、预期及delivery分工。总用例在test-cases.md维护并生成cases.csv；API数据驱动组合从执行源生成api/data-cases.csv，完整参数不进入总表。兼容查询数据仍由plan生成。复杂KYC准备、权限恢复、并发竞争与对账放在`scripts/filbet/`的小型业务模块，通用执行和报告放在`scripts/qa_core/`；结果目录不存放可执行脚本。

API覆盖规则、边界、权限、状态和数据正确性；手动覆盖展示、交互、反馈、预览和代表性用户流程。人工表不复制API的全参数矩阵。数据库只读。既有新需求UI定位在`ui/data/isop2027.json`，保留兼容；当前新需求UI使用人工清单。P0页面资产、用例和执行入口继续维护。

环境继续复用既有Python/JS加载器；敏感账号由忽略的本地配置按actor引用。`.env.ui-p0.fat`仍被旧资金入口使用，不能按键名重复删除。新需求不继承旧资金profile的写入范围。

## 结果与清理规则

- 新需求真实执行写`reports/qa/<Story>/<run-id>/`，保留result.json、用例/计划快照和必要失败证据。默认只生成results.csv/results.html，`--extra-views`按需生成用例/失败/未执行CSV及summary.json。
- 团队执行包包含api-auto.csv和manual.csv；导入只接受明确来源，校验环境、契约、批次及证据。离线准备/导入/重建不更新最近实测指针，不制造PASS。
- latest只表示最近一次真实执行，可为局部复验。旧归并演示、旧API批次已清理，不能继续导入；旧日期结论不是本次重测证据。
- 2026-09-11清理是用户授权的一次性整理，没有启用按5次/30天等自动留存策略。后续报告清理须核对当前执行包、活动运行、待评审证据及业务恢复所需状态。
- SQLite、扫描游标、确认/去重/待发送状态及号码预留不是可重建报告。本次保留活动Telegram任务及状态；旧异常会员只保留本机标识索引，未操作业务现场。
