## 当前结构

具备执行资产的需求使用`requirements/<Story>/plan.json`维护用例、验收点、契约、参数集、actor、步骤、预期及delivery分工。总用例在test-cases.md维护并生成cases.csv；API数据驱动组合从执行源生成api/data-cases.csv，完整参数不进入总表。兼容查询数据仍由plan生成。复杂KYC准备、权限恢复、并发竞争与对账放在`scripts/filbet/`的小型业务模块，通用执行和报告放在`scripts/qa_core/`。当前2090共享实现位于`scripts/filbet/loss_rebate*.py`，本单CLI只编排；没有`plan.json`／`api/cases.json`，不为满足结构预建空计划；结果目录不新增可执行脚本，也不作为公共代码导入来源。

常用逻辑沿已有模块维护，确认有重复需求后再提炼；长期方法、模块规则分别落在`skills/`和`modules/`。低频专项保留Jira／文档定位和必要决定，使用时核对原资料，不为归档需求扩建常驻脚本。日常保留判断见[资产规则](architecture.md#常用能力与资料保留)。

API覆盖规则、边界、权限、状态和数据正确性；手动覆盖展示、交互、反馈、预览和代表性用户流程。人工表不复制API的全参数矩阵。数据库只读。既有新需求UI定位在`ui/data/isop2027.json`，保留兼容；当前新需求UI使用人工清单。P0页面资产、用例和执行入口继续维护。

环境继续复用既有Python/JS加载器；敏感账号由忽略的本地配置按actor引用。`.env.ui-p0.fat`仍被旧资金入口使用，不能按键名重复删除。新需求不继承旧资金profile的写入范围。

## 结果与清理规则

- 新需求真实执行写`reports/qa/<Story>/<run-id>/`，保留result.json、用例/计划快照和必要失败证据。默认只生成results.csv/results.html，`--extra-views`按需生成用例/失败/未执行CSV及summary.json。
- 团队执行包包含api-auto.csv和manual.csv；导入只接受明确来源，校验环境、契约、批次及证据。离线准备/导入/重建不更新最近实测指针，不制造PASS。
- latest只表示最近一次真实执行，可为局部复验。旧归并演示、旧API批次已清理，不能继续导入；已退出或已缺失的原始证据不能由日期摘要替代，旧日期结论不是本次重测证据。
- 2026-10-16用户要求及时清理无用历史资料；按当前执行包、活动运行、待处理BUG和业务恢复依赖判断，不新增按5次/30天等无差别自动留存策略。实际删除、此前已缺失及保留项分别记[整理记录](project-cleanup-2026-10-16.md)。
- SQLite、扫描游标、确认/去重/待发送状态及号码预留不是可重建报告。这些状态不按报告清理；旧记录提到的本机索引和队列须核实可用性，不能因文档写过保留就假定当前仍在。本次未操作业务现场。
