# 统一需求工作流

2026-09-14实现。`npm run qa`复用现有接口扫描、计划执行、人工包和BUG分析模块；原`qa:telegram`、`qa:requirement`及P0命令保持兼容。统一工作流当前只执行FAT固定计划，不自动建单或发群；独立CLI能力不由此推定。2026-10-05当前仅ISOP-2100，尚无固定API计划；状态可维护不表示自动执行已就绪，归档范围见[整理记录](project-cleanup-2026-10-05.md)。

## 日常入口

```bash
# 打开可编辑、持久保存的需求状态页
npm run qa -- status --serve

# 一次完成接口同步、提测扫描、AI用例草稿、前置检查、就绪API执行和HTML报告
npm run qa -- run --execute

# 只读刷新远端接口文档；固定读取origin/main，不切换接口仓库分支
npm run qa -- sync --fetch

# 单独生成带来源的AI草稿，不修改原用例或执行计划
npm run qa -- generate ISOP-2100

# 离线检查单个或全部需求；BLOCKED退出码2
npm run qa -- check ISOP-2100

# 扫描并按既有授权执行就绪固定API计划，不重新生成草稿
npm run qa -- scan --execute

# 仅用保存的扫描记录检查，不联网/不执行
npm run qa -- scan --offline
```

`run`默认处理一轮后退出，不启动常驻扫描器；通过`--execute`才执行已授权固定计划。`run --offline`只同步本地接口提交、读取本地提测记录并检查。`--offline`与`--execute`不可组合。`--source`指定Bruno目录，`--ref`固定Git提交；默认沿用本机已有目录，可在其他机器显式传入路径。`--fetch`只取远端引用，不pull/reset/checkout用户目录；不带该参数不声明远端最新。

## 接口增量与需求关联

同步读取固定提交的Bruno归档，复用现有scanner更新`api/inventory`、`api/catalog`，不更新P0范围。首次建立基线，后续比较上次提交，记录新增/修改/删除、路径、内容hash和关联依据；历史重写拒绝自动前推。文档中的明确Story编号、需求资料引用的同一路径，以及[业务目录映射](../config/workflow-documents.json)分别标注来源。没有依据的文档留unmatched，不猜成已提测。

映射修订产生独立版本的变更记录，不覆盖旧证据。未提交的接口仓库修改不进入提交快照，也不被清理。2026-09-14的实现验证用交接已核验的b8daa7d建立基线，再同步本机231d55d，2份投注返利文档按2032业务范围关联推断；该记录未核验远端和部署，不代表当前接口版本。

## AI草稿和执行前检查

AI仅接收按文件列出的脱敏需求上下文，通过现有Codex只读分析适配生成结构化草稿，保存JSON、CSV、来源hash和未决问题。运行时检查唯一ID、真实来源、验收点引用、前置、步骤、预期、数据要求和阻塞。没有已确认验收点的测试建议必须附阻塞原因，单独标记BLOCKED_EXPECTATION；未知引用仍拒绝。缓存按源文件及schema内容hash区分；源变更会重新生成。模型失败保留日志，不回退到旧输出，不覆盖原`test-cases.md`或`plan.json`。如本地校验规则修订，可显式使用`generate ISOP-2028 --validate-output`复核已有输出；只有来源上下文逐项一致才接受，不再次调用AI。

生成的草稿不是已批准业务规则，也不直接执行AI代码。功能预期和API断言按[人工确认流程](testing-workflow.md#人工确认预期与断言)评审，现有程序没有额外的人工签字门禁。固定计划继续由同一执行器运行。前置检查包括业务用例与API组合关联、计划schema/hash、需求和环境、已授权写范围以及适配器离线检查。样本真实性与独立预期在实际运行时继续核对，离线READY不等于业务就绪或通过。尚无统一计划的需求显示缺口，原CLI继续保留。

[执行策略](../config/workflow.json)绑定当前固定计划hash与既有授权。计划变化后须完成本地检查，再更新对应hash；不能直接接受AI草稿来绕过检查。策略只列已有范围，当前未自动开启新增写权限。2022暂停不能通过页面改状态解除；必须有用户重新开测指令并更新暂停策略。

归档需求由统一工作流前置检查和队列执行入口共同拦截，旧队列记录也不能绕过。归档表示移出当前范围，不自动新增完成、上线或业务PASS。历史资料仍可按明确编号定位；独立CLI历史回归须另有明确范围与授权，页面人工改状态不会恢复执行资格。

## 提测触发与执行证据

触发需要明确FAT环境及接口提测依据，AI默认填入的FAT不当已确认环境。UI通知、未知环境、不确定/撤回消息、未完成分析、未就绪计划保持待办。版本未提供沿用已有FAT例外并记录未核验。执行前只读核对Jira父Story，重查计划、来源与授权；事件按Story、环境、版本、消息ID、计划/来源/策略hash去重。

事件先持久记录RUNNING再执行。重复事件不重跑；崩溃或INTERRUPTED保持不确定状态，不能自动重放写请求。调查完旧现场后，以新修复/重新提测事件明确发起下一轮。新编排不消费旧Telegram确认、不恢复旧任务，也不写outbox。BUG HTML沿用`qa_delivery.pipeline`报告渲染；固定执行失败和AI分类失败都原样保留，空候选不表示无缺陷。

## 状态页面和持久化

[状态HTML](../requirements/status.html)为可随仓库打开的导出快照，离线查看以页面标明的来源为准；`status --serve`提供本机`127.0.0.1:8765`页面，`--port`可改端口。页面默认只看当前需求，可切换归档或全部；归档原始静态报告已退出时显示退出说明和历史路径。服务从固定报告路径读取已完成的真实API批次，排除人工汇总、UI自动批次和未完成检查点。每个需求分别展示API自动证据、API人工修订、UI人工验收及完整修订历史；不由最近局部PASS关闭整单。

修改状态必须填修改人、来源和原因；更新采用版本比较，并追加历史，旧值不被删除。UI人工通过不会覆盖API失败，归档项的人工修订不改变归档归属。修改人是本地填写的来源记录，不是多人登录认证。进入UAT等业务含义由人工来源记录；此页面没有新增Jira状态自动同步器。

数据在忽略的`reports/workflow/state.sqlite3`，文档差异、AI草稿和执行报告也按版本/事件隔离在该目录。HTML只是一份可重建视图，SQLite及证据目录需一起备份；不要按测试报告清理。`--state`可选择隔离的本地状态目录。离线导出从实际状态目录计算证据相对路径；Windows跨盘时使用本机文件URI，在线页面仍使用受限`/evidence/`路由。迁移来源保留在[历史记录](../requirements/history/records-through-20261005/status-history-20260914.md)，初始数据不是实时状态的第二维护入口。

页面只开放本地状态读写和白名单证据，不提供业务执行、文件任意读取或BUG提交接口。保存要求同源和随机令牌；不依赖浏览器localStorage，因此换浏览器或重启服务不丢记录。

## 历史实现验证（2026-09-14）

当时新增离线测试覆盖增量提交/删除/工作区保留、来源引用校验、API/UI证据隔离、手工修订持久化与并发冲突、事件去重、暂停/UAT/变更计划拦截、HTTP同源和私有文件隔离、BUG HTML转义。实际执行过本地接口增量同步、6个候选的离线评估，以及真实`scan --execute`：获取2条更新、pending_analysis=0，当时6个候选均因各自缺口没有触发业务执行。当前校验记录见[交接](../AI-HANDOFF.md)。

实际Codex生成曾被自动审批以具体上下文发送未明确授权拒绝；用户随后明确授权本轮脱敏需求生成验证，已完成2028真实生成。17条草稿中14条关联已有验收点但仍有数据/契约阻塞，3条权限/非法参数建议标记BLOCKED_EXPECTATION。来源未变化的结构化输出已离线复核保存，未把这些草稿当可执行计划或产品通过。真实新消息→固定API→BUG候选全链路及新业务回归尚未实测，UAT明确不在本轮。
