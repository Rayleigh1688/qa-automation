# 代理系统：三套后台基线

[模块入口](../README.md) · [2100需求入口](../../requirements/ISOP-2100/design.md) · [2100问题与决定](../../requirements/ISOP-2100/questions.md) · [环境规则](../../api/runbooks/ENVIRONMENTS.md)

本页是代理系统的长期来源与规则基线草稿，覆盖代理后台、独立代理管理后台、管理后台代理模块。页面实况、接口响应和日期结论由各轮执行记录保存；本页不表示三个系统已完成验收，也不新增自动化门禁。

当前BUG结果与验证边界见[10-05回归](regression-20261005.md)；[初轮整体摸底](verification-20261005.md)保留当时快照及后续账号准备。三端路由／认证和查询校准从[后台操作手册](../../api/runbooks/ADMIN.md#代理三套服务的只读定位)进入。此处只维护长期规则与来源，不复制实时数字。

用户最新明确：独立代理管理后台首页不再展示本次所查数据，后续代理整体回归跳过该首页及其BI／图表读口；代理自己的首页仍按2100核对。初轮历史首页观察不作为当前该入口缺陷或验收门槛。

## 三套入口的职责

| 入口 | 使用者与职责 | 关联范围 |
| --- | --- | --- |
| 代理后台（代理端） | 外部代理查询自己的直属会员、推广信息及业绩 | 2100改造首页看板、会员列表、会员日统计；登录身份决定数据范围 |
| 代理管理后台（独立运营端） | 内部运营审核代理申请，管理代理、会员、推广域名及系统配置；保留角色、员工和操作日志等管理能力 | 沿既有代理系统及各模块来源核对；2100未列入此入口的页面改造，不由此推定完全没有关联影响 |
| 管理后台代理模块 | 内部运营查看代理身份与关系、代理统计及会员统计，并进行跨页面核对 | 2100涉及代理统计报表、会员日统计的个人统计页签；直接转代理另有独立来源 |

三套入口分别核对环境、角色和服务路由。主管理后台登录成功不证明独立代理管理的审核权限可用；后台员工身份、会员代理资格与代理端登录身份也不是同一状态。历史上存在逐步弱化独立代理管理、将功能移回主管理的规划，不能把规划当成迁移已完成。

FAT入口及候选API定位见[入口复核](../../requirements/ISOP-2100/entry-review-20261002.md)和[代理链路定位](../../requirements/ISOP-2100/chain-api-20261001.md)。其中日期结果仅代表原批次，使用前重新核当前环境，不机械替换域名或沿用旧token。

## 规则的采用顺序

1. 先读用户最新决定及对应需求正文，明确入口、功能、适用日期和执行范围。2100采用[问题与决定](../../requirements/ISOP-2100/questions.md)及[本期范围核查](../../requirements/ISOP-2100/acceptance-20261005.md)，不复制当前通过率或失败计数。
2. 未被新需求覆盖的既有功能按上表原始来源核对。旧默认当月、每日人数相加、点代理账号进入会员详情等行为，不能覆盖2100的默认本日、区间去重及带代理／日期进入会员日统计要求。
3. 技术评论、接口文档、源码和页面用于定位实现与数据来源。彼此冲突时记录具体端点、字段、单位或行为，不由当前显示反推产品定义，也不从文档样例补造可执行参数。
4. 缺少规则、样本或权限证据时明确保留未知；文档已读取、菜单可见、接口HTTP200与业务正确分别记录。来源工单状态不替代修复复验。

代理指标的符号、JP、时间、Bonus及跨日人数规则进入[2100 Q-03](../../requirements/ISOP-2100/questions.md#q-03)，更新容差进入[Q-05](../../requirements/ISOP-2100/questions.md#q-05)，日期上限及两端独立进入[Q-08](../../requirements/ISOP-2100/questions.md#q-08)。首页BI、好友活动和代理报表的同名指标不自动共用所有公式。

## 身份、关系与审核边界

- 代理关系与好友邀请链独立。代理端只能读取自己的直属会员；主管理所属代理筛选不能用邀请人代替。当前关系、统计当时关系快照与历史转线各自核对，不通过转线或改库修补数据。
- 现有注册归属还包括代理域名匹配。原始PRD规定二级域名优先于子域名，再优先于参数；二级域名命中时覆盖其他参数。只看到推广码或注册成功，不能判直属绑定成立。
- 推荐码记录的`uid`是所属代理，记录中的`parent_uid=1`可以是该代理自身的顶级位置，不等于新会员绑定结果。复现须查新注册会员主档的`parent_uid/parent_name`、一级关系树及代理直属名单。网页参数`u`对应代理推荐码，不能用好友邀请`i`代替；实际注册应核`invite_code`和表示入口主机的`domain`头。现有通用注册辅助默认不发送`domain`，不能单独当作网页域名绑定验证。
- 域名配置以匹配类型＋域名为唯一组合；新增、编辑、删除及启停依对应权限。后台保存配置与运维完成解析分别核对，不把配置记录存在当作域名已经生效。
- 客户端申请与管理直接开通是不同路径。申请资料要求Email、FB Messenger Username及同意协议，四个问题可选，视频已划除；驳回需展示原因并支持再申请。当前`can_apply_agency`完整资格公式未由这些资料定义，不能由KYC状态同时出现推定因果。
- 直接转代理来源规定：未开通资格按钮可用，已开通置灰；未通过KYC者随开通转为FULLYKYC，并增加KYC和代理审核记录；结算方式默认周结、类型正常。具体写入按单独批次授权，接口与验后态流程见[直接开通手册](../../api/runbooks/ADMIN.md#主管理直接开通业务代理)，不同于客户端申请或后台员工授权。
- 推广码既有规则包括格式、大小写不敏感与不可重复；修改推广码后新链接对应更新，旧码／旧链接仍可绑定。具体接口参数及关系结果继续对照[链路契约](../../requirements/ISOP-2100/chain-api-20261001.md)，不只按最新码判旧链接失效。
- 角色权限按既有主管理标准实现的来源没有完整角色允许矩阵。先核当前角色、页面及只读接口范围，按钮可见不足以证明后端授权；不自行编造角色权限预期。

## 停佣后的核查边界

停代理佣金计算与派发是2100已确认要求，见[Q-06](../../requirements/ISOP-2100/questions.md#q-06)。代理端佣金报表、佣金账变及礼金页面退出；代理端会员日统计不提供总佣金；好友邀请佣金保持独立。

独立代理管理中的历史佣金记录、结算属性或旧配置仍存在，本身不证明继续计算／派发。页面菜单退出也不能证明后台已停。采用可取得的只读配置、运行或记录证据，并结合准确停用时点区分历史与新增；不追加指定任务名、日志格式或派发探针作为唯一证明方式，不擅自清理、审核、补发存量。

旧代理总开关同时控制佣金结算和关系绑定，并联动客户端入口及代理后台登录子开关。停佣后的耦合是否保留须结合新决定和实现核对；不能把总开关当独立佣金调度开关，也不能为了测试绑定或登录开启它。旧60天看板／31天图表范围不自动应用到2100页面；2100的90天范围也不自动扩到未改造的独立代理管理页面。

## 本次整体只读检查范围（2026-10-05）

用户在完成本期需求功能核查后，追加检查三个代理系统整体。此轮可观察页面与真实查询结果，不以2100五处改造限缩所有检查，也不覆盖[09-16后台模块整理约定](../README.md)；后者仍适用于其原模块工作。

| 检查范围 | 可取得的证据 | 执行边界 |
| --- | --- | --- |
| 入口、登录与菜单 | 环境／角色、可见菜单、页面和已知服务路由 | 正常fresh登录；同账号API／UI串行，不更改密码或切换实际角色权限 |
| 列表、筛选、排序、分页、详情与导出 | 页面条件、对应查询参数／响应、下载内容及数据集合 | 只读既有资料；仅调用已确认的查询契约，方法是POST不等于写入，方法是GET也不自动等于只读 |
| 代理／会员身份和关系 | 既有资格、当前上级、推广码／域名配置、两端对应行 | 不新增会员、申请、审批、直接开通、转线、封禁、余额调整或域名配置 |
| 数字与数据一致性 | 同一代理／日期的看板、列表、统计、源记录及历史快照 | 优先复用既有样本；数据库只读；不充值、投注、提现、重算或造数补足样本 |
| 停佣、配置、权限与审计 | 已有配置、角色范围、日志及可解释的历史／新增记录 | 不改总开关、佣金方案、角色／员工配置，不审核或派发佣金；查询不到记录不判已停止 |

未知参数或时间单位先核[现有接口复核](../../requirements/ISOP-2100/contract-review-20261001.md)及实际契约，不用猜测周期编码、字段或成功接口继续推进。敏感身份、凭据、token和原始个人资料留忽略目录，跟踪文档只保存脱敏定位与必要聚合。问题先按现有来源及[交付流程](../../docs/telegram-qa.md#bug-delivery)去重，本轮整体查看不自动授权提单、改工单状态或发群。
