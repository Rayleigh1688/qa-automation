# KYC：问题与决定

[功能基线](README.md) · [API验证清单](test-cases.md)

2026-09-16首轮。已确认内容引用长期规则和2027决定；下列缺口仅影响相应断言，不阻塞模块资产整理。

| 编号 | 分类 | 当前问题与下一步 |
| --- | --- | --- |
| Q-01 | 已有规则与UI冲突 | 编辑表单用户留言仍禁用；用户已确认可以修改，不再询问产品。需核对前端部署/权限并定位实现，当前仅有本角色本表单观察，不能推定API回退 |
| Q-02 | 已补规则；EKYC本轮略过 | 2026-09-16用户确认EKYC基本不会再开，本轮不验证其自动审核、失败/超时、开关组合和存量影响。EKYC提供玩家上传证件和人脸识别界面；三方验证开启才调用三方验证接口，关闭时不调用，仅提供上传接口。规则记录不代表已经实测 |
| Q-03 | 查询口径待核 | 名称精确/模糊、手机号/UID切换、提交/审核时间选择、默认月份边界、渠道范围及今日通过/待审计数是否受筛选影响；本轮仅发现控件 |
| Q-04 | 状态/接口映射待核 | 初审动作全集、Rejected筛选可见性与状态枚举；复核state、review_status及页面选项映射复用已有计划并验证，不把KYC状态与复核状态混用 |
| Q-05 | 沿用既有未决项 | 原因精确长度、权限矩阵剩余边界、分行跨表映射、并发/故障恢复见2027问题与报告，不重新设计重复问题；本轮未复测 |
| Q-06 | 已解决/用户确认 | 2026-09-16用户确认重复资料目前仅颜色标记，无其他行为；不得仅因重复标记设计自动驳回、禁止提交或禁止审核通过的预期。具体重复判定和字段映射仍需从接口/实现核对 |

规则已明确：手机号与KYC状态不可通过资料编辑修改；用户留言可改；草稿核准前正式资料不变；本人不可自审；驳回原因必填；编辑复核期间拦截会员新提交/补件；空集约定仅在既定查询范围复用。
